## 2026-07-25 認証ガードの修正と開発環境の移設

### 問題
ログイン済みでトップページを開くと、ヘッダーには「今月のカレンダー」が出ているのに本文は「まずは登録/ログインしてください」という矛盾した画面になっていた。

### 原因（4つが重なっていた）
1. `app/page.tsx` が認証を見ない静的な案内ページだった。PWA の `start_url` が `/` なので直撃していた
2. `middleware.ts` が Cookie の**存在**しか見ておらず、`auth-token=dummy` のような値でも保護ページを表示していた（本番で 200 が返ることを実測で確認）
3. `/api/auth/me` が無効トークンでも 200 で `{user:null}` を返し、SWR が成功と解釈していた
4. calendar / list / account でそれぞれ扱いがばらばらだった

### 対応
- `lib/edge-token.ts` を新設。Edge Runtime で使える Web Crypto 版の HS256 検証（既存トークンとの互換を9ケースで検証済み）
- `middleware.ts` で署名と有効期限を検証。無効なら Cookie を削除してリダイレクト。`/api/*` は 401 JSON
- `app/page.tsx` を `/calendar` へのリダイレクトに変更
- `/api/auth/me` を 401 に変更
- SWR が 4xx でリトライしないように `onErrorRetry` を追加
- Header の赤い「セッションが無効です」表示を廃止し、401 のときだけ自動遷移（通信エラーでは遷移しない）
- calendar ページの重複した Cookie チェックを撤去

### 安全側に倒した設計
`AUTH_SESSION_SECRET` が読めない場合と検証が想定外に失敗した場合は、middleware は**従来どおり通過させる**。ここで全リクエストを弾くとサイト全体が停止するため。認可は各 API 側でも検証される。

### 同時に対処したこと
- `cookies.txt` が2件コミットされていた。ルート側に実トークンが含まれていた（2025-10-23 失効済み・管理者権限なし）。追跡解除して削除し `.gitignore` に追加
- プロジェクトを `~/Desktop/Codex CLI/month challenge/` から `~/dev/month-challenge/` へ移設

### 移設の理由と効果
Desktop 配下は iCloud 同期の影響でファイル読み込みが極端に遅く、開発が事実上できない状態だった。

| 項目 | 移設前 | 移設後 |
|---|---|---|
| ファイル読み込み | 73秒 | 0.022秒 |
| `npm install` | 数分 | 7.4秒 |
| 型チェック | 7分44秒 | 1.3秒 |
| dev サーバー起動 | 起動せず | 2.7秒 |

`mv` は iCloud 側でブロックされて進まなかったため、GitHub から clone し直し、Git管理外の `.env` 系と `.vercel` を手動で移した。

## 2025-11-01 Redis → Neon データ移行

本番が Redis をプライマリストレージにしていたが、キャッシュ機構は Neon にしか対応しておらず機能していなかった。Neon 単一構成に統合した。

- ユーザー: 34 → 37人
- エントリー: 65 → 482件（417件追加）
- 孤児エントリー26件（削除済みユーザーのデータ）と、古い不正な日付形式12件はスキップ
- Vercel から `REDIS_URL` を削除

移行に使ったスクリプトは `scripts/` に残っている（`analyze-migration.js` / `migrate-redis-to-neon.js` / `migrate-entries-only.js`）。

## 2025-10-02 「今月のカレンダー」ボタンのJST対応

`Header.tsx` が `new Date().toISOString()` を使っており、JST午前0時〜8時59分の間は前月が表示されていた。年またぎでは前年12月が出る問題もあった。`getJstTodayDate().slice(0, 7)` に修正。

---

## 2025-09-30 JST日付処理バグ修正

`/api/entries/today/route.ts` が `new Date().toLocaleString()` を使っており、JST午前0時台のスタンプが前日として記録されていた。`getJstTodayDate()` に修正。既存の誤記録データは管理画面から確認できる。
